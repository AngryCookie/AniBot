# Отчёт по внедрению Referral Core Layer

## Что реализовано

Реализован backend-слой реферальной системы без Discord-команд и без web UI:

1. **Новые ORM-модели** для хранения связей, наград и настроек рефералок.
2. **Миграция схемы БД** для создания новых таблиц и индексов.
3. **Расширение ReferralService** с ядром бизнес-логики:
   - создание реферальной связи;
   - выдача signup-бонусов;
   - выдача activity-бонусов;
   - проверки от абуза и ограничений;
   - запись выплат в историю наград.
4. **Интеграция с EconomyService** через `EconomyService.credit()` для всех начислений.

---

## Какие таблицы созданы

### 1) `referral_links`
Хранит факт связи «кто пригласил кого» внутри гильдии.

Поля:
- `id` (PK)
- `guild_id` (индекс)
- `referrer_user_id` (индекс)
- `referred_user_id` (индекс)
- `created_at` (UTC now)

Ограничения:
- `UNIQUE(guild_id, referred_user_id)` — один приглашённый может иметь только одного реферера в рамках сервера;
- `CHECK(referrer_user_id != referred_user_id)` — защита от self-referral.

### 2) `referral_rewards`
Журнал начислений по реферальной системе.

Поля:
- `id` (PK)
- `guild_id`
- `referrer_user_id`
- `referred_user_id`
- `source_type` (тип источника награды)
- `amount`
- `created_at`

Назначение:
- аудит выплат;
- аналитика по типам наград (signup/activity и т.д.);
- подготовка данных для панели и отчётов.

### 3) `referral_settings`
Гильдейские настройки реферальной механики.

Поля:
- `guild_id` (PK)
- `enabled`
- `signup_bonus_referrer`
- `signup_bonus_referred`
- `activity_percent`
- `activity_duration_days`
- `milestone_level`
- `milestone_bonus`
- `max_referrals_per_user`

Назначение:
- централизованная конфигурация и фича-флаг для конкретного сервера.

## Как работает защита

В `ReferralService.create_referral(...)` реализованы проверки:

1. **Self-referral блокируется** сразу на уровне сервиса (`referrer_user_id == referred_user_id`) и дополнительно CHECK-констрейнтом в БД.
2. **Повторная привязка приглашённого блокируется**:
   - проверкой существующей записи под блокировкой (`SELECT ... FOR UPDATE`);
   - `UNIQUE(guild_id, referred_user_id)` как жёсткая гарантия от race condition.
3. **Лимит `max_referrals_per_user`**:
   - считается текущее число рефералов у реферера;
   - при превышении создаётся ошибка и запись не добавляется.
4. **Транзакционность**:
   - создание связи + начисление + лог наград выполняются в одной DB-транзакции;
   - при ошибке весь блок откатывается.
5. **Защита от гонок (race conditions)**:
   - чтение ключевых строк/настроек под `FOR UPDATE`;
   - финальная защита уникальным индексом и обработкой `IntegrityError`.

## Интеграция с EconomyService

Реализована интеграция через `EconomyService.credit()`:

- `handle_signup_bonus(...)`:
  - начисляет бонус рефереру (`referral_signup_referrer`);
  - начисляет бонус приглашённому (`referral_signup_referred`);
  - пишет обе операции в `referral_rewards`.

- `handle_activity_bonus(...)`:
  - рассчитывает бонус как `activity_amount * activity_percent`;
  - начисляет рефереру (`referral_activity_referrer`);
  - пишет запись в `referral_rewards`.

Таким образом, реферальные начисления попадают в общую экономику и в стандартный экономический ledger/transaction trail.

## Что уже готово для web panel

Готов backend API-уровня (модель данных + сервисная логика), который можно напрямую обернуть REST/GraphQL-эндпоинтами:

- чтение/редактирование `referral_settings`;
- просмотр `referral_links`;
- просмотр истории `referral_rewards`;
- агрегации по типам наград и пользователям;
- безопасное создание реферальной связи через `create_referral`.

---

## Что уже готово для Discord UI

Готова серверная бизнес-логика для будущих команд/ивентов:

- обработчик создания связи (`create_referral`);
- автоприменение signup-бонусов при создании связи;
- отдельный обработчик activity-бонусов;
- устойчивость к дублям и злоупотреблениям;
- полная интеграция выплат с экономикой бота.

Дальше можно безопасно добавить:
- slash-команды управления настройками;
- команды статистики по рефералам;
- хэндлеры onboarding/verification event-ов, которые будут вызывать core-сервис.
